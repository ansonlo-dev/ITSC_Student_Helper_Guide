# 故障排查手冊

有方法勝過死記硬背。跟著以下步驟，即使面對從未見過的問題，你也能有所進展。

## 1. 弄清楚問題

按這個次序發問：

- 你原本想做什麼？
- 結果實際發生了什麼？（請對方一字不漏地說出錯誤訊息。）
- 上一次正常運作是什麼時候？
- 之後有什麼改變 —— 換了密碼、換了裝置，還是做過更新？
- 是每次都出現，還是只是間中出現？

::: tip 一定要拿到錯誤訊息
「它出錯了」不算資訊。請用戶把畫面給你看，或者讀出訊息內容。大部分錯誤訊息本身
就已經給了答案。
:::

## 2. 界定影響範圍

這一條問題最能節省時間：

> 是 **這一位用戶**、**這一部機器**，還是 **所有人**？

| 範圍 | 可能成因 | 行動 |
| --- | --- | --- |
| 一位用戶，任何機器 | 帳戶、配額、權限 | 檢查帳戶 |
| 一部機器，任何用戶 | 硬件、本機設定、線材 | 檢查機器 |
| 所有人 | 網絡、伺服器、服務中斷 | 立即升級處理 |

## 3. 先檢查最簡單的東西

大致按「最常是答案」的次序排列：

1. 有沒有開機、有沒有插電 —— **兩端** 都要檢查？
2. 是否用對了裝置、對的插口、對的輸入訊號源？
3. Caps Lock、鍵盤語言、用戶名打錯字
4. 有沒有連上網絡／連對 Wi-Fi？
5. 問題出現之後有沒有重啟過？
6. 是否有已公布的服務中斷或維修時段？

## 4. 用替換法逐步隔離

一次只換一個變數，藉此證明問題出在哪裡：

- 同一用戶，換另一部機器
- 換另一位用戶，同一部機器
- 換另一條線、另一個插口，或另一個轉接頭
- 換另一個瀏覽器，或用無痕視窗

## 5. 修好之後要驗證

- 改一樣，測一次。切勿一次過改多樣東西。
- 讓 **用戶** 自己確認可以了，並做回他原本想做的事。
- 把試過但沒有幫助的改動還原。

## 6. 知道何時應該停手

::: warning 15 分鐘原則
若 15 分鐘內毫無實質進展，或者開始有人龍，就升級處理。升級不等於失敗；讓用戶
一直卡住才是。
:::

遇到以下情況，不需排查，立即升級：

- 整個電腦室、整棟大樓或整項服務中斷
- 帳戶權限、保安，或懷疑帳戶被入侵
- 可能有資料遺失
- 用戶動怒或想要作出投訴

## 7. 記錄下來

寫下：用戶報告的問題、影響範圍、你試過什麼、最後是什麼解決了，以及仍未處理的
事項。要包含機器名稱和房號 ——「窗口旁邊那部電腦」對任何人都沒有幫助。
